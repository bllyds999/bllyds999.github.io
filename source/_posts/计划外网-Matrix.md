最后编者还是下定决心，给 Matrix 开了一个外网端口，虽然说能用，但没有之前在内网这么快了。原因是 Cloudflare 会对反复递包的设备拦截，部分数据包直接丢了，有时候会导致无法登录。但好在当你登录上去以后就能一直挂着，收到消息什么的也是即时的，不会出现啥登录上去了也收不到的情况。已经建立连接以后，速度就会快很多，没有之前那种卡顿的感觉了。对比 MagicDNS，因为域名都是自己的，所以一个域名下可以有很多个子域名。编者可以把这些子域名分配给 ntfy 和 Matrix 服务，这样用起来就能省心很多。但值得一提的是，用 Cloudflare Tunnel 暴露 Matrix 的话，网络地址是根据 CLoudflare 服务部署位置看的。

直接裸机在 UNIX 部署，可以填写 `localhost` 之类的；但如果你是在容器里面部署的，比如编者之前举例子的 Synapse Docker 部署方案，那你就要填写机器在内网的 IP 地址，`localhost` 此时指代容器本身。部署好了，编者也不打算把域名公开出来：编者用的是自己的家庭服务器，也就是编者那个树莓派。不能开放注册，不然就要备案、管理，但 Matrix 天生是逆管理的，内容加密到本地完全不知道别人在说什么，也不能整啥拦截。而且自己用着这样就挺好，要不然到时候又被别人知道了，直接挂上了自己的个人主页，于是乎编者的网站就被搜索引擎索引了。不过这个索引有办法应对，开启 Coudflare 的 `robots.txt` 就可以了。
