description: "本文描述了一位技术爱好者在硬件和软件兼容性方面的折腾经历，核心围绕着如何在 M4 芯片上为《我的世界》提供运行环境，特别是运行不支持 GL 4.1 的光影模组。叙述者从最初使用 RTX 4060 电脑的经历，转而对 X86 架构产生不信任，最终选择了 M4 MBA，因为它提供了优秀的 UNIX 生态支持。然而，M4 芯片有一个硬伤，即无法原生运行 GL 4.6 及以上的高级图形渲染。为了解决这一问题，叙述者尝试了多种方案，包括利用社区模组 Vitrail 将 GL 光影以 Vulkan 的方式运行在 M4 上，以及关注 MGL 等项目。尽管 M4 性能在打包和编译软件方面表现出色，但图形兼容性仍是挑战。叙述者在寻找解决方案的过程中，经历了从技术难题到自我发现的转变，最终发现自己所需的答案竟然存在于自己几个月前发布的一篇过时文章中。这段经历生动地展现了在高度冷门的图形渲染和游戏模组领域，技术探索所伴随的复杂性和幽默感。"

编者最近几天因为国庆假期景区堵，身上没什么零用钱，选择不去远地方游山玩水，一心折腾在 macOS 上跑 GL 4.6，主要是为了给《我的世界》提供运行环境，其实现在 Vitrail 模组也能解决部分问题。重点就是为了让几个不支持 4.1 的光影跑在 M4 芯上，但对编者来说其实《我的世界》里其它社区光影也够玩了，但你耐不住人就是为了折腾而生的。其实这种问题并不是很时候，因为曾经编者是有一个 RTX 4060 电脑的。至少那个电脑已经可以解决如今的问题了，但编者确确实实把它给卖掉了，Linux 的操作和生态兼容以及 Windows 的垃圾广告像头皮藓一样折腾编者。编者已经对 X86 不信任了，但当时接触到了一台二手 MBA Intel 2020。

这台两千块的低成本二手机，让编者入坑了 macOS，也让编者知道了其实编者已经找到了答案。后来在 RTX 4060 电脑长期格式化硬盘的损伤，以及 MBA 的卡顿以后，编者卖掉了这两台机器，换上了这台 M4 MBA。它解决了编者最大的需求，系统不是 Windows 的，其次就是 UNIX 的支持做得非常好，因为它自己就是 UNIX。对于 M4 的性能编者是一忍再忍，因为编者主要是打包、编译软件、打打游戏，比 Linux 的 RTX 兼容好。不会让编者想起曾经在 Arch 下滚系统，N 卡新旧驱动打架导致无法更新了。虽然 M4 很优秀，但它有个硬伤就是无法跑 GL 4.6 以上的东西，开始编者认为只需要 Vulkan 就能解决，毕竟现在 Vulkan 是常态。

但编者貌似忽略了《我的世界》这个意外，它的社区大头依然在使用 GL，但官方已经在很明显推 VK 了。目前社区的 Vitrail 模组已经可以把 GL 光影以 Vulkan 的方式运行在 M4 上，但兼容性毕竟不是很好。编者想起了之前 VulkanMod 和 Beryl 刚起来的时候，在社区里看见有人在 RTX 上跑 Caustica 模组，它是一个光追模组。编者又想起了自己刚把原神账号注销一年，结果今年在社媒发现原神玩家理智了，福利好了。不禁让编者想起自己的小学母校，在编者升学离开以后，忽然就变成了一所装修漂亮的小学。新来的通红塑胶跑道和已经装修好的精致教学楼，都是编者六年下来都没有见过的东西，甚至编者一年级的时候操场还是真的草。

联想起自己小学三年级知识都还没成体系，教科书突然换版了，导致编者成绩突然变差，而低年级从入学起就是这套书。我去网上查找了 MGL 这个项目，它貌似可以解决我的问题，但它只是个人维护项目——能用。其它站长的研究我都没有看到，编者往下翻全都是别的社区的内容。直到编者看到有一篇文章很眼熟，又是光影运行又是什么的，就你了。点进来一看，居然是编者前几个月的过时文章。足以见得，编者涉及的领域多冷门了。编者核查了那篇文章，用 Markdown 划掉了当时一知半解的内容，并在开头增加了提醒标识。那篇文章的涉及 Zink 和 Mesa 的部分是错的，但 Photon 那部分是对的。以为自己是个小博主，结果搜教程搜到自己了。
