在 Mojang 最新发布的 26.3 正式版中，一个重大的技术决策被采纳：Vulkan 选项被设置为默认开启。这一改变标志着 Minecraft 在图形渲染路径上的一次根本性转变。当用户的显卡具备 Vulkan 支持时，游戏会自然地路由到 Vulkan 渲染引擎；如果硬件环境不支持 Vulkan，系统则会回退到传统的 OpenGL 渲染模式。这种默认设置的引入，使得 Vulkan 在 Minecraft 的地位从过去一个可选项，迅速跃升为未来的第一等公民。这一转变无疑为游戏带来了更高的性能潜力，但也为依赖现有生态系统的社区带来了新的挑战和机遇。尽管如今 Vulkan 是第一公民，但社区在长久中积累了大量依赖 OpenGL 接口的社区作品。

这些成熟的生态系统，无论是功能性还是视觉效果上，都建立在 OpenGL 的基础之上。因此，当核心渲染管线转向 Vulkan 时，社区面临的首要任务，就是确保这些依赖 OpenGL 的作品能够在新范式下继续运行，尤其是光影效果的实现。社区为此投入了巨大的精力，开始积极准备，试图为 Vulkan 模式下的光影效果“开光”。在众多试图解决 Vulkan 光影生态问题的加载器中，目前主要有 3 个知名的项目：Sulkan、Beryl 和 Vitrail。其中，Sulkan 采用了全新的渲染范式和光影格式，代表了一种前沿的尝试。而 Vitrail 则展现出独特的价值，它专注于在如今的 Vulkan 平台上，尝试兼容原本的 OpenGL 格式光影包。

在目前的社区关注中，Vitrail 被认为是解决 Vulkan 光影生态问题的最有希望的加载器。虽然当前运行在 Vitrail 上的 GL 光影帧数，尚未能直接达到纯粹 GL 模式下的最高帧数，但它展示了在 Vulkan 模式下还原熟悉光影效果的可能性。就在最近的开发周期中，贡献者乙为 Vitrail 提交了一个针对 26.3 版本的新合并请求。最初由贡献者甲提交了 26.3 分支合并请求，但代码与 26.2 版本存在不兼容问题，未能通过审核。贡献者乙随后创建了新的分支来解决这一兼容性问题。然而，新分支在 26.3 上仍有一个问题：即使已开启 Vulkan，点击光影包列表中的某一行也没有反应，因为该行仍在用 GLFW 的左键判断。

我在 GitHub Actions 上编译并测试该分支的 Fabric 版本时发现该问题。分支贡献者的升级日志里也写明，开发过程中未对 Fabric 版本进行充分测试，所以这个 Bug 的出现并不意外。就在今天的下午，我收到了作者对该提交的积极回复。作者对这个可选版本的新分支表示非常满意，并承诺不会急于合并代码，但会协助该分支贡献者完善代码，并最终合并到主线。这为社区带来了极大的信心，我们很快就能拥有一个功能完备的 26.3 Vitrail，这无疑是一个令人振奋的好消息。期待我们都能够在 26.3 这一优化较好的版本，为我们枯燥的游戏世界添加一丝光彩。如有疑惑的，本文附上了[原贴链接](https://github.com/avpbynf/Vitrail-Shaders/pull/430)，可以去看看。
